What went well during development is that I consistently improved the game through iterative, feedback-driven updates and validated/tested the changes as I went. Instead of trying to do everything at once, I shipped polished and focused updates (tile readability, HUD cleanup, enemy clarity, settings UX, and character selection), which made the game noticeability stronger and polished each step of the way. I also added resilient systems, not just visual changes, including persistence for character and progress settings and safer audio crashes when the mixer fails. Another strength was debugging flow issues between screens: crashes tied to stale input and initialization order were diagnosed and fixed at the root level, which stabilized the transition between start screen, character selection, and gameplay. As for the group dynamic we worked really well together. Gavin and I were able to communicate throughout the duration of the semester on what we wanted to achieve and we were able to meet and discuss any last-minute changes we wanted to work on, despite having troubles with another group member.

What went wrong is that the source control friction and merge conflicts would repeatedly interrupt my momentum. Divergent branch pulls and rebases caused avoidable delays, and conflict-heavy files needed careful manual reconciliation. I also let a temporary testing value leak into gameplay (current_level = 3), which made the game start on Level 3 until it was caught and corrected. Finally, one conflict resolution pass removed required helper functions from the start screen while leaving calls intact, which broke launching and had to be immediately repaired. Overall, the project improved a lot technically and visually, but the reliability of merge workflow and stricter final checks would have saved time and prevented regression movements. 

If I started over, I would have taken more time to tune the game’s visual aesthetic. Colors, sound effects, and music were viewed as secondary tasks throughout development, as the main focus between now and the first demo was adding more content to the game in the form of levels, enemies, and power-ups. I would have experimented with different colors for the levels and their items (i.e., colors of the floor, walls, coins, enemies, and power-ups), as well as different background music tracks to curate a more intentional visual aesthetic.

Initially, the rate at which the tiles disappeared and dealt damage to the player did not change, which made the levels easy and anticlimactic. In order to give the game an intense sense of urgency as the player reaches later levels in the game, we implemented a system in which the speed that the tiles disappear increases as the player levels up.
